# Events implementation plan

Implements the user-approved events work item, ER §10/12 and ADR 0006.

## Design

Keep an immutable event log and a receipt per consumer/event. Only SQL publishers can append events through `private.publish_event`; API roles cannot execute that helper. Service-role RPCs read pending events and atomically upsert receipts, preserving successful receipts and incrementing failed attempts. Pending reads exclude processed and exhausted receipts, without a cursor. Delivery is at least once: downstream handlers must queue side effects with event-based deduplication before resolving.

The server-only runner accepts explicit consumers, validates envelopes and publisher-owned payload schemas, records safe failure codes, and isolates consumers. A secret-protected POST route is the composition root; it starts with an empty consumer list. The kick helper awaits a bounded POST inside the publisher's `after()` callback. No cron or downstream feature implementations.
